- 使用 Docker 生产镜像 `voice-assistant:local`（0.1.32）；`fast_chat.py` SHA256 与本地主干一致，见 metadata.json。
- 请求经过真实 FastAPI `/v1/chat` 的认证、中间件和处理逻辑，使用 ASGITransport 在进程内调用；未经过公网反代、TCP 或客户端 UI。
- 正常用例使用真实 Clef 分类、真实 ChatCompletion、独立真实 Harness 和 Memos 0.30.0；逐例重置合成备忘，并读回实际存储正文。
- 仅 PocketBase 会话历史写入替换为隔离内存列表，故障例 F01–F04 注入指定异常/模型响应；未验证真实故障发生概率。
- 固定模型时间为 2026-10-04 16:00:00 星期日。线上搜索结果依执行时来源，不能保证索引覆盖截至固定时间的最新内容。
- 未验证麦克风录音、ASR、TTS 或目标应用实际回贴。
- 首次隔离 Harness 未加载 CLIPROXYAPP_API_KEY，造成查询拆词失败；补齐与生产一致的该项凭据后，查询及后续用例全部重跑。报告只计入有效样本，记录类 48 个有效样本保留。

## 失败项与建议

### P1 文本生成任务误写 Memos（P03, P04）

6/6 次错误新增备忘并返回 speak。

证据：Clef 同时返回 intent=record、delivery=paste；后端 record 分支优先于 paste 分支。

建议：让分类问题明确区分保存备忘与写文本、总结；在模型决策层处理相互矛盾的结果，不用关键词强行改路由。

### P1 搜索关键词覆盖正确的记录意图，写到了临时文件（A03）

3/3 次未写 Memos，Harness 用 bash 写入 todo.md，却回复已记录。

证据：Clef 本来返回 record；fast_chat.py 的 search_keywords 覆盖随后把 intent 改成 agent。

建议：移除或收紧关键词覆盖，由模型依据整句语义区分记录将来的搜索事项与立即执行搜索。

### P2 证件无法召回护照记录（Q02）

3/3 次搜索为空，而同一 fixture 的 Q01、Q06 都返回正确位置。

证据：关键词拆解产出证件，单次 CEL 使用字面 contains，未覆盖护照这种下位概念。

建议：让拆词模型产生受控的同义词或下位概念检索词，仍保持一次 CEL 查询；用不确定答案避免“没检索到”等同于“从未记录”。

### P2 联网检索结果相关性与时效性不足（A01, A02）

A01 1/3 次未给出剧名；另外两次经多轮检索才回答，耗时约26–29秒。A02 3/3 次未拿到最新官方资料。

证据：工具实际执行了，但初始 FreeSerp 结果包含无关站点或旧资料；A01 多次用 bash 继续检索，A02 某次执行了第二次搜索，均偏离 preset 的一次搜索约束。

建议：评估检索源的相关性与时效性，技术问题优先官方来源；用工具执行预算控制单次搜索与延迟，不只靠提示词约束。
