# Watch 界面与流式播报验证

日期：2026-10-04。回退 tag：`watch-ui-before-streaming-20261004`（提交 `a91e16f3e9`）。

## 完成范围

答案优先、折叠原话、语义字号与段落、固定录音按钮及音量反馈、时长、独立底部操作区、可发现的设置入口。录音启动前不初始化播放引擎。识别失败可显式重试原录音；聊天请求不自动重试。中断保留已接收文字并提示，新录音取消旧任务。

`POST /v1/chat` 新增 `stream`（默认 false）及流式请求的 `response_style=watch`。真实模型 content 增量以 SSE delta 发出，done 携带完整结果；心跳和 error 明确区分等待、中断、成功。原 JSON 客户端不受影响。工具最终结果/备忘写入确认只在执行后输出一次，不伪造 token。详细契约见 `watch_app/README.md`。

Watch 首段文字到达即准备语音，首句或 400ms 缓冲后请求 TTS，后续句子合并排队，PCM 到达后立即调度播放。停止播报不会停止文字生成，再说取消两条链路。已有自动播报关闭偏好保留，新安装默认开启。

## 验证结果

- Debug 和 Release watchOS Simulator 构建成功。
- 40 项受影响 Python 测试通过：流首段提前到达、取消关闭生成、失败无 done/不重跑、鉴权、参数校验、默认 JSON、原 fast-path/音频/查询行为。
- `RecordingLaunchPolicy` 8 项检查通过；`SpeechTextBuffer` 验证跨 chunk 句子拼接、长段拆分、尾段无重复。
- 本机 Device Hub，watchOS 27.0：46mm Series 12 和 40mm SE 3。检查了待机、录音权限及录音页、设置入口、长文触摸滚动至第 8 条和原话入口、大字体、取消返回待机后重新录音、流中断保留文字。
- 确定性延迟上游使用真实 API 路由及 OpenAI SSE 解析器，外部模型/音频替换为 fixture，不写个人记忆或历史。Watch 日志：17:35:18.761 首段文字，17:35:19.378 发起 TTS，17:35:19.408 首块 PCM，17:35:22.800 文字完成；音频比完整文字提前约 3.39 秒。
- 真实上游通过本机 API 单独测试：聊天 HTTP 200，约 4.25s 首段/5.07s 完成；Gemini TTS HTTP 200，约 2.65s 首块，收到 209280 字节 PCM。
- Watch 连接本机真实 API 完整测试：17:42:11.396 首段文字，17:42:11.827 发起 TTS，17:42:11.844 文字完成，17:42:14.366 首块真实 PCM，随后完成全部播放。该短回答生成很快，音频实际播放晚于文字完成，但合成请求在生成期间开始；真实 TTS 网络延迟不能由界面消除。

## 验证边界

仅本机 API 和模拟器，未部署 Docker API 或更新实体手表。真实触觉、抬腕/熄屏及设备上的语音质量仍需真机测试。模型生成速度和 TTS 延迟决定实际声音是否早于完整文字；系统保证首段到达后提前开始合成，不保证所有短回答都能提前出声。
