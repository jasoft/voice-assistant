# 语音助手项目任务入口：实施计划

日期：2026-10-07。执行：ZCode / GLM-5.3-Flash。工作目录：`/Users/weiwang/Projects/voice-assistant`。

## 目标与用户体验

大王在外面通过现有语音助手（包括 Apple Watch）说需求，系统识别项目，把原始需求交给家中 Mac 上的 Codex 或 Antigravity 执行。任务必须出现在对应工具原有的聊天列表里，大王可以打开原工具查看、补充；也可以继续通过语音助手查询进度、补充要求和停止任务。

例如：

- “让 Codex 给语音助手加上任务进度查询。”→ 识别 `voice-assistant`，创建原生会话，立即告知“已交给 Codex，开始后会更新进度”。
- “让 Antigravity 修一下千问项目里的图片拖拽。”→ 识别 `comfyui`，在对应项目创建 Antigravity 原生会话。
- “刚才那个做得怎么样了？”→ 查询刚才任务的真实状态。
- “继续刚才那个，回答尽量短一点。”→ 原生会话保持不变，追加这条用户指令。
- “把刚才那个任务停下来。”→ 停止对应任务，读回停止状态。
- “把语音助手再增强一下。”→ 功能要求不足时只问一个简短问题，明确需求后再创建任务。

默认执行工具先用 Codex；用户明确指定工具时遵从用户。项目可以配置自己的默认工具。

## 实现约束

### 接入方式

优先使用原工具现有原生接口；Codex 可检查共享 app-server/proxy 与 thread/turn 接口；Antigravity 可检查原生 CLI 的项目选择、stream-json 和 conversation 续接。不能通过伪造数据库/会话文件/聊天 UI 完成接入。

参考 Codex 官方资料：

- https://developers.openai.com/codex/app-server
- https://developers.openai.com/codex/noninteractive

本机当前支持的参数以现场帮助和原生协议为准，不照搬旧命令。启动/恢复必须绑定明确项目和原生会话 ID，不能使用全局“最后一个会话”误接其他项目。

### 服务端与 Mac 的职责

语音服务端负责语义解析、项目选择、任务登记、进度查询和语音回答；Mac 执行器负责本机项目目录、原生工具调用、会话续接和结果回传。已有远程调用方式若能完成全部契约可以复用；否则采用 Mac 主动连接/领取任务，沿用现有语音服务入口，避免新增公网接入面。

服务器维护小型持久化任务记录，使用现有持久化目录。至少区分 queued/running/waiting/completed/failed/cancelled，记录 native_session_id、更新时间和最新可用结果；支持幂等提交/领取，防止并发领取和网络重试重复执行。状态必须来自执行器/原工具事件，不能由模型编造。

新任务立即返回接收状态，不能一直占住聊天连接等待编码结束。Mac 离线时明确提示排队/暂不可执行；启动失败时明确报失败，不把“已登记”说成“已经开始执行”。

### 用户隔离与输入边界

沿用现有认证并核验实际配置。执行器仅处理配置的用户和登记项目；新任务接口不能沿用“任意未知 token 都能自动成为用户”的宽松行为。查询、续接、停止都要校验任务所有者。

模型只输出结构化任务字段，不能决定任意本地路径或拼出待执行 shell。传给工具的是参数数组和原始需求；账号沿用已登录工具，不更换账号，不拷贝或输出认证信息。沿用原工具权限策略，遇到必要审批返回 waiting/需要处理的状态，不以关闭保护来绕过。

### 代码与部署

先读取项目和所触及子目录的 `AGENTS.md`。保持小改动，执行层沿用行为树结构，提示词放外部 JSON，日志写 stderr。不要增加录音启动前的耗时操作，不重写 Mac/Watch UI。

Python 依赖使用 uv，命令使用 rtk，搜索用 rg/fd。确需 Mac GUI 修改时做 Release build；服务端修改合并 main 后必须运行 `./scripts/deploy.sh`，远程操作先读 shell 项目的 `AGENTS.md`。新增配置同步远程，但凭据只存本地/远程现有私有环境配置。

只提交本次改动，保留开始前已有的 `uv.lock` 修改及后来出现的他人工作。部署脚本要求干净工作区时，可在包含本次 main 提交的干净 worktree 执行，不能为了通过检查提交/丢弃无关改动。若分支/worktree 工作，完成后合并 main 并 push origin；不要删除不属于本任务的工作树。

## 必须验证的场景

| 场景 | 预期 |
| --- | --- |
| 语音助手项目的明确需求 | 选择正确项目和目录，创建一个原生会话，回执与真实启动状态一致 |
| 千问项目别名或语音同音字 | 由模型理解，指向登记的 comfyui 项目，不误改 voice-assistant |
| 明确选择 Codex / Antigravity | 遵从用户；工具不可用时报告原因，不默默换工具 |
| 在原工具打开任务并补充 | 列表可见，会话 ID 一致，语音侧随后查询能反映实际进展 |
| 查询/继续刚才任务 | 当前用户上下文正确，沿用原会话，不创建重复任务 |
| 停止正在执行的任务 | 原工具确实停止/中断，服务器读回相符状态 |
| 要求太模糊或项目不明确 | 简短澄清，未确认项目或目标前不启动修改 |
| 普通聊天、记录、查备忘、粘贴 | 仍走原有路径，不误派发为项目任务 |
| 未认证、跨用户 ID、未登记项目/目录 | 拒绝，不能读到/操作别人的任务或任意目录 |
| 重复请求、并发领取、服务重启、Mac 离线 | 不重复执行，状态有解释，可继续查询 |
| 远程部署后的手机/手表聊天入口 | 使用真实生产入口验证文本→转交→结果；没有设备实测的环节单独标明未验证 |

真实链路测试用明确只读的短任务，例如“只读检查当前项目名称和 Git 分支，回复结果，不修改任何文件”。不要把“增强项目”这种示例当作实际测试任务让工具自行扩改。
