# 语音助手问句与响应测试集

共 40 条设计用例，面向 `POST /v1/chat`。本文件是验收规格；JSON 版本在 `tests/scenarios/chat_acceptance.json`。首次执行已完成，每条重复 3 次，见 [执行报告](reports/chat-acceptance-2026-10-04/report.md)。

## 验收方式

- 响应示例用于说明语义，不做逐字匹配。检查路由、`action`、Memos 写入次数和语义条件，分别报告路由正确率、正文保真率、写入正确率。
- `record` 必须先调用一次 ChatCompletion，再调用 Memos 创建；从真实日志确认调用顺序，从 Memos 读回正文及语音原文。不能只凭成功提示或 `summary_s` 字段判定通过。
- 所有正常记录用例：正文符合该行条件、恰好新增一条私有备忘、完整保留语音原文及 `#voice`，返回的确认内容与存储正文一致。不要求总结文字与示例逐字一致。
- `query` 只能检索，`chat` 不检索，回贴不写备忘；应监测 Memos API 调用次数，不能只看响应 `memories` 是否为空。
- `expected.intent` 表示入口路由；回贴成功的响应 `debug_info.intent` 当前为 `compose`，agent 慢路径的调试格式可能不同，路由以分类日志与工具调用为证据。
- `action=paste` 的 API 验收只证明后端生成正文。若做完整 GUI 验收，还需确认目标应用获得正文、未播 TTS；没有辅助功能授权时允许复制到剪贴板的既有降级。

## 测试准备

1. 使用独立测试实例和独立 Memos 账号/库；每例重置，仅装入该例指定的 fixture。不要把虚构测试内容混入个人真实备忘。测试结束清理本次创建的记录并读回确认。
2. 在测试服务设置 `PTT_CURRENT_TIME=2026-10-04 16:00:00 星期日`，所有固定日期断言以此为准；在线搜索答案依执行时来源，不冻结结果。
3. 文本输入直接测语义链路；转写纠错另用真实音频测 `/v1/transcribe → /v1/chat`，不能仅凭手写问句宣称 ASR 已验证。
4. 故障例在隔离测试中用 mock 或代理注入，不停生产服务、不改真实凭据。Memos 写入超时可能结果未知，不应简单断言零写入；本集使用明确拒绝验证失败提示。
5. 正常用例建议每条重复 3 次，记下每次 route/action/正文/请求 ID/新增 memo ID/耗时。延迟目标：正常 fast-path ≤8 秒，另报 P50/P95；agent 与故障例单独统计，不承诺 8 秒。
